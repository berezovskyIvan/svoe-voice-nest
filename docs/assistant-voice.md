# WS /api/assistant/voice — живая транскрипция

Зависимость — [общая обработка команды](./assistant-text.md). Одна запись соответствует одному WebSocket-соединению.

## Контракт

| Направление | Сообщение | Назначение |
| --- | --- | --- |
| NestJS → Nuxt | `{"type":"ready"}` | Сервер готов принять аудио |
| Nuxt → NestJS | Бинарные кадры | Моно PCM 16-bit signed little-endian, 16 кГц, без контейнера |
| Nuxt → NestJS | `{"type":"stop"}` | Последний кадр уже отправлен, можно завершать распознавание |
| Nuxt → NestJS | `{"type":"cancel"}` | Отменить запись и закрыть поток |
| NestJS → Nuxt | `{"type":"transcript","text":"Закажи молоко"}` | Весь текущий текст, которым Nuxt заменяет предыдущий |
| NestJS → Nuxt | `{"type":"recognized","text":"Закажи молоко 3,2%"}` | Итоговый текст, можно показать состояние обработки команды |
| NestJS → Nuxt | `{"type":"result","data":{...}}` | Тот же объект, что возвращает текстовый эндпоинт с `X-Zoya-Contract: nuxt` |
| NestJS → Nuxt | `{"type":"error","error":{"code":"NO_SPEECH","message":"Не расслышала. Повторите, пожалуйста"}}` | Терминальная ошибка |

После `result` или `error` сервер закрывает соединение. После `cancel` или отключения до начала обработки команды освобождает ресурсы SpeechKit. `unknown` приходит как `result`. Коды ошибок — `INVALID_AUDIO`, `NO_SPEECH`, `RECORDING_LIMIT`, `STT_UNAVAILABLE`, `ASSISTANT_UNAVAILABLE`.

## NestJS

- Поднять WebSocket и открыть двунаправленный gRPC-поток SpeechKit v3 на запись. Хранить учётные данные в окружении сервера. Отправить параметры сессии до аудио, настроить `LINEAR16_PCM`, `ru-RU`, внешний EOU и нормализацию текста.
- Собрать зафиксированные сегменты и текущую промежуточную гипотезу. По `stop` отправить SpeechKit сигнал EOU после последнего кадра, дождаться финальных сегментов и нормализации в пределах тайм-аута. Использовать `final_refinement` для замены соответствующего `final` по индексу. При наличии финального текста использовать его даже если нормализация не успела прийти.
- Отдать `recognized` и вызвать общую обработку ровно один раз. Повторный `stop` игнорировать. Для пустой записи вернуть `NO_SPEECH` без вызова YandexGPT.
- Ограничить запись 30 секундами и входящий буфер, установить тайм-ауты завершения. Закрывать gRPC при отмене, обрыве и ошибке. Описать WS-протокол рядом со Swagger для HTTP.

[Потоковое распознавание SpeechKit](https://aistudio.yandex.ru/ru/docs/speechkit/stt/streaming) · [Формат аудио, EOU и события gRPC](https://aistudio.yandex.ru/ru/docs/speechkit/stt-v3/api-ref/grpc/Recognizer/recognizeStreaming)

## Nuxt

- Открывайте новое соединение для каждой записи и дождитесь серверного `ready`. Событие браузера `open` означает только установление соединения.
- Для захвата используйте Web Audio, например AudioWorklet. Приведите аудио к одному каналу, ресемплируйте до 16 кГц, преобразуйте отсчёты в signed Int16 little-endian и отправляйте двоичными кадрами. Например, 100 мс аудио дают 3200 байт. Кадр должен иметь чётную ненулевую длину и занимать не более 32 000 байт. WebM/MP4 из MediaRecorder относятся к отдельному HTTP-контракту.
- Лимит сессии записи — 30 секунд с момента готовности сервера. После отправки `stop` дождитесь серверного `result` или `error`. Если соединение закрылось без терминального события и пользователь его не отменял, покажите возможность повторить ввод.

- Запрашивать доступ к микрофону по действию пользователя. Через Web Audio получать и приводить сигнал к формату контракта, отправлять кадрами после `ready`. Проверить запись на браузере и устройстве питча.
- Отобразить ожидание, запись с живым текстом, паузу с возможностью продолжить, обработку, результат и ошибку. На паузе прекратить отправку кадров с речью, а при продолжении возобновить её. По остановке сначала выгрузить остаток аудио, потом послать `stop`. Автоотправка по тишине для двух сценариев не требуется.
- Освобождать микрофон и соединение при отмене и уходе с экрана. При отказе в доступе, обрыве или ошибке дать перейти к текстовому вводу. Обрабатывать `result.data` так же, как HTTP-ответ.

## Приёмка

- Текст меняется до остановки. После остановки видно финальный текст и открывается правильный результат для обоих сценариев.
- Несколько финальных сегментов складываются в одну фразу. Два события остановки дают один результат.
- Тишина, неподдерживаемая команда, отмена и сбой SpeechKit дают разные исходы. После отмены или обрыва соединения можно начать новую запись.
