# «Зоя» MVP — задачи и контракты

Документ описывает план реализации для закрытого показа. Согласованы Nuxt 4, NestJS, PostgreSQL, один тестовый пользователь Екатерина без авторизации и живая транскрипция через Yandex SpeechKit.

- Фермерские продукты → проверка распознанной команды → корзина внутри Nuxt → явное подтверждение → результат.
- Аналитика трат → предложение вклада под 14% → калькулятор → явное подтверждение → результат.
- Команда на открытие вклада → калькулятор → явное подтверждение → результат.

## Подключение Nuxt 4

Локально NestJS слушает `http://127.0.0.1:8080`. Добавьте публичную настройку в `nuxt.config.ts` и задайте `NUXT_PUBLIC_ZOYA_API_BASE` для стенда.

```ts
export default defineNuxtConfig({
  runtimeConfig: {
    public: {
      zoyaApiBase: 'http://127.0.0.1:8080',
    },
  },
})
```

Значение — origin API без `/api`. Для HTTPS-страницы используйте HTTPS API и WSS. При раздельных доменах задайте на бэкенде `FRONTEND_ORIGIN` равным origin страницы Nuxt, например `https://demo.example.com`, без завершающего слеша. Бэкенд уже разрешает `http://localhost:3000` и `http://127.0.0.1:3000`. При использовании reverse proxy передавайте `/api/*`, `/static/*` и WebSocket Upgrade на один и тот же бэкенд. Все операции работают с одним демо-счётом без авторизации.

### HTTP-запросы

`X-Zoya-Contract: nuxt` обязателен для получения описанных здесь форматов истории и текста. Заказ и вклад выбирают формат по полям JSON. Для обеих операций нужен UUID в `Idempotency-Key`.

```ts
const baseURL = useRuntimeConfig().public.zoyaApiBase
const nuxtHeaders = { 'X-Zoya-Contract': 'nuxt' }

const menu = await $fetch('/api/actions/history', {
  baseURL,
  headers: nuxtHeaders,
})

const result = await $fetch('/api/assistant/text', {
  baseURL,
  method: 'POST',
  headers: nuxtHeaders,
  body: { text: 'На что я больше всего потратила в этом месяце?' },
})

// Создайте UUID в браузере при явном подтверждении.
// При сетевом повторе сохраняйте и UUID, и исходное тело.
const confirmation = {
  key: crypto.randomUUID(),
  body: { amount: 800_000 },
}
const deposit = await $fetch('/api/actions/deposit', {
  baseURL,
  method: 'POST',
  headers: { 'Idempotency-Key': confirmation.key },
  body: confirmation.body,
  retry: 0,
})
```

Для заказа покажите `delivery.address` в корзине и отправьте `items: [{ id, qty }]`, `expectedTotalPrice`, `deliveryDate: delivery.date`, `deliverySlot: delivery.slot` и `deliveryAddress: delivery.address`. В `items` оставьте только ID и количество упаковок. При изменении количества пересчитайте `expectedTotalPrice` как сумму `price × qty`. Если API вернул `PRICE_CHANGED`, покажите обновлённый итог из `error.details` и дождитесь нового подтверждения с новым UUID. После успеха загрузите историю заново. Она содержит актуальный баланс, тогда как повтор подтверждения возвращает баланс на момент исходной операции.

При HTTP-ошибке `$fetch` выбрасывает исключение. Код и текст API берите из `exception.data?.error?.code` и `exception.data?.error?.message`. Если ответа нет, покажите сетевую ошибку. Для повтора подтверждения после тайм-аута или обрыва отправьте сохранённые тело и UUID.

Ссылку на фото собирайте как `new URL(item.imageUrl, baseURL).href`. Swagger UI доступен по корню API, JSON-схема — по `/openapi.json`. В OpenAPI описаны оба HTTP-формата, поэтому для выбора полей используйте примеры ниже.

### Голосовой сценарий

Открывайте WebSocket в браузере после действия пользователя. URL строится из того же origin API.

```ts
const url = new URL('/api/assistant/voice', baseURL)
url.protocol = url.protocol === 'https:' ? 'wss:' : 'ws:'
const socket = new WebSocket(url)
```

Дождитесь `ready`, затем отправляйте моно PCM 16 кГц, signed 16-bit little-endian. После последнего кадра отправьте `{"type":"stop"}`. Заголовок `X-Zoya-Contract` для WebSocket не нужен. Обрабатывайте `result.data` той же функцией, что и ответ текстового эндпоинта. По `farmer-products` откройте черновик корзины, по `analytics` покажите траты и предложение вклада, по `deposit` откройте калькулятор вклада, по `unknown` покажите сообщение и оставьте доступным повторный ввод. Подробности приведены в [голосовом контракте](./assistant-voice.md).

## Правила сценариев

- WebSocket занимает путь `/api/assistant/voice`. Запасной способ отправить команду — текстовый HTTP-эндпоинт.
- В корзине можно изменить количество упаковок. Помощник предлагает дату и утренний слот, берёт адрес из команды или подставляет демо-адрес. Оплата идёт с общего демо-счёта. Переход в корзину выполняет Nuxt по интенту `farmer-products`.
- Вклад в рублях на 6 месяцев, ставка 14% годовых, сумма редактируется. Для калькулятора описано упрощённое правило расчёта дохода. Условия и счёт фиксированы.
- История содержит успешные ответы аналитики и подтверждённые действия. Детали по нажатию, платёж ЖКХ, лимиты, озвучка ответов и следующие вопросы аналитики остаются за рамками двух сценариев. Для полного сброса стенда используется локальная команда. HTTP-сброс исходного контракта оставляет траты и каталог.
- TypeORM и его миграции используются как источник схемы. Деньги в API и БД — целые рубли. Активируются только подсказки двух сценариев. Даты доставки и периоды аналитики рассчитываются в `Europe/Moscow`. `createdAt` передаётся как ISO 8601 в UTC, Nuxt форматирует его для отображения.
- Успешная HTTP-операция возвращает `200`. Ошибки возвращаются в виде `{"error":{"code":"INVALID_REQUEST","message":"Проверьте поля запроса"}}`. Дополнительные поля конкретных ошибок описаны в задачах.

## Порядок интеграции

1. Поднять PostgreSQL, собрать бэкенд и выполнить `yarn demo:seed`. Использовать примеры ответов ниже для моков Nuxt.
2. Проверить текстом оба сценария до экранов успеха и истории. Параллельно поднять один поток до SpeechKit на устройстве для показа.
3. Подключить голос к той же обработке, прогнать оба сценария, повтор подтверждения и сброс стенда.


## Структура NestJS

- `src/assistant` — обработка команд, аналитика и YandexGPT.
- `src/actions` — подтверждение заказа и вклада, списание и история.
- `src/voice` — WebSocket, сессия распознавания и SpeechKit.
- `src/persistence` — подключение PostgreSQL, запросы, миграции и демо-данные.
- `src/shared` — правила доставки и вклада, подбор товаров и ошибки.


## Исходный HTTP-контракт

[Исходное ТЗ](./backend-spec-zoya.md) описывает базовый HTTP-формат.

Без `X-Zoya-Contract` запросы истории и текста возвращают формат исходного ТЗ.
`POST /api/assistant/voice` принимает WebM или MP4 в поле `file` и требует установленный `ffmpeg` с `libopus`. Голосовой WebSocket использует формат Nuxt.
Формат подтверждения определяется по полям тела запроса. Исходный клиент может передать UUID в `Idempotency-Key` для безопасного повтора. Если дата заказа отсутствует, используется ближайший доступный утренний слот.
`POST /api/actions/reset` восстанавливает баланс и стартовую историю. Для обновления старых демонстрационных трат используйте `yarn demo:reset` на демо-базе.
