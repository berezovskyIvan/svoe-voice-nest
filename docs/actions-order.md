# POST /api/actions/order — подтверждение заказа

Зависимости — [черновик корзины](./assistant-text.md), [каталог и баланс](./foundation.md).

## Контракт

Заголовок `Idempotency-Key` — UUID одного подтверждения. Повтор с тем же телом возвращает исходный результат. Повтор с тем же ключом и изменённым телом возвращает `409 IDEMPOTENCY_CONFLICT`. При изменении корзины после ответа об ошибке фронт создаёт новое подтверждение с новым ключом.

```json
{
  "items": [{"id": 1, "qty": 1}, {"id": 2, "qty": 1}, {"id": 3, "qty": 1}],
  "expectedTotalPrice": 497,
  "deliveryDate": "2026-11-21",
  "deliverySlot": "09:00-12:00",
  "deliveryAddress": "ул. Садовая, 15"
}
```

```json
{"orderId": 6, "totalPrice": 497, "newBalance": 1799503}
```

Для MVP `orderId` — идентификатор записи заказа в истории. Передавайте `deliveryAddress` из `delivery.address`. Это необязательное поле для обоих форматов подтверждения. При отсутствии поля используется «ул. Красная, 122». Стоимость доставки — 0 ₽. `qty` — целое число упаковок из каталога от 1 до 100. В корзине допускается до 100 позиций. В запросе каждый товар допускается один раз.

В старом формате с полем `totalPrice` также можно передать `deliveryDate` в формате `YYYY-MM-DD`. Если дата отсутствует, сервер использует ближайший доступный утренний слот.

| HTTP | Код | Когда возвращается |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | Пустая корзина, повтор товара, некорректное количество, поля или ключ |
| 404 | `PRODUCT_NOT_FOUND` | Один из товаров отсутствует в каталоге |
| 409 | `DELIVERY_UNAVAILABLE` | На указанную дату и интервал оформить доставку нельзя |
| 409 | `PRICE_CHANGED` | Итог отличается от показанного. `error.details.totalPrice` и `error.details.items` содержат актуальный итог и позиции в формате черновика |
| 409 | `INSUFFICIENT_FUNDS` | Итог выше текущего остатка |
| 409 | `IDEMPOTENCY_CONFLICT` | Повторное использование ключа с другим запросом |

## NestJS

- Провалидировать запрос, загрузить позиции, посчитать `sum(price × qty)` на сервере. `expectedTotalPrice` используется для сверки перед списанием. Просроченный или неизвестный слот отклонять по общему правилу доставки.
- В одной транзакции PostgreSQL заблокировать строку демо-счёта, проверить повтор подтверждения, вычислить сумму, проверить баланс, списать деньги и сохранить снимок заказа, результат и запись истории. Снимок хранит товары, дату, слот и адрес на момент подтверждения.
- При повторе вернуть сохранённый ответ вместе с `newBalance` на момент оригинального списания. Актуальный баланс для меню берётся из эндпоинта истории.

## Nuxt

- Открыть корзину на внутреннем маршруте и пересчитывать итог по показанным ценам при изменении количества. Заблокировать подтверждение пустой или неполной корзины.
- Отправлять запрос только по кнопке «Оплатить». На время запроса отключить кнопку, при сетевом повторе использовать исходный ключ. При смене цены обновить корзину и дать заново подтвердить итог.
- После успеха показать экран оформленного заказа и обновить историю.

## Приёмка

- Корзина из трёх демопозиций списывает 497 ₽. Форма показывает ту же сумму, что и результат и запись истории.
- Изменение количества приводит к одинаковому расчёту на клиенте и сервере. Изменение отправленной суммы без изменения товаров даёт `PRICE_CHANGED`.
- Двойное нажатие и повтор после потери ответа дают одно списание и одну запись. Ошибка цены, доставки или баланса сохраняет исходное состояние счёта.
