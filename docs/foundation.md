# Общие задачи — PostgreSQL, каталог и стенд

## Локальный запуск

Для локального PostgreSQL используйте `docker compose up -d --wait postgres`. Укажите `DATABASE_URL` из [шаблона окружения](../.env.example) в существующем `.env`. Для своего PostgreSQL используйте адрес выделенной демо-базы. Для работы ассистента нужны `YC_FOLDER_ID` и `YC_API_KEY` сервисного аккаунта с доступом к YandexGPT и SpeechKit.

```sh
yarn install --frozen-lockfile
docker compose up -d --wait postgres
yarn build
yarn demo:seed
yarn start:prod
```

`yarn demo:seed` применяет миграции и добавляет стартовый счёт, историю, траты текущего месяца и 100 товаров. Повторный запуск сохраняет оформленные операции. Для повторного показа используйте `yarn demo:reset` на выделенной демо-базе. Сброс возвращает баланс и историю к исходному состоянию.

HTTP по умолчанию доступен на `127.0.0.1:8080`. Если reverse proxy обращается к API через отдельную сетевую границу, задайте `HOST` для нужного интерфейса. Swagger UI открывается на `/`, машиночитаемая схема — на `/openapi.json`. Для Nuxt с другого адреса укажите его полный origin в `FRONTEND_ORIGIN`. Локальные `http://localhost:3000` и `http://127.0.0.1:3000` уже разрешены. Голос использует тот же хост и порт по пути `/api/assistant/voice`.

## PostgreSQL и демо-данные

- Подключить PostgreSQL через `@nestjs/typeorm` и миграции TypeORM. Описать настройки окружения в `.env.example` без ключей. Для стенда понадобятся `DATABASE_URL`, параметры сервисного аккаунта и моделей Yandex Cloud, адрес Nuxt и параметры приложения.
- `accounts` хранит одну запись с Екатериной и стартовым балансом 1 800 000 ₽. Оформление заказа и открытие вклада используют общий счёт и блокировку его строки.
- `products` хранит идентификатор, название, категорию, цену, размер упаковки и путь к изображению. Закрепить идентификаторы трёх товаров из демонстрационной корзины и наполнить каталог сотней позиций из требования. Загрузку и подготовку каталога запускать отдельно от приложения.
- `transactions` хранит категории, положительные суммы расходов и временные метки. Демо-аналитика строится из сидовых трат текущего месяца. Заказ и вклад обновляют счёт и историю помощника, а демо-набор аналитики остаётся стабильным на протяжении прогона.
- `assistant_history` хранит дату, тип, заголовок, подзаголовок и сумму. У подтверждённых действий хранить ключ, нормализованный запрос и снимок результата для безопасного повтора. Сделать уникальность ключа в пределах типа операции, с учётом того, что демо-счёт один.
- Сделать повторяемый сид и отдельную локальную команду сброса для организатора. Сброс восстанавливает баланс, стартовую историю и набор трат на текущий месяц, сохраняет каталог и очищает сохранённые подтверждения вместе с историей. Выполнять сброс между прогонами, когда пользователи не оформляют операции.

## GET /static/products/:filename — изображения каталога

- Снимок 100 позиций хранится в [demo-catalog.json](../src/persistence/demo-catalog.json) с исходными карточками и URL фотографий. Первые три позиции используют цены закрытого демо. Порция творога 400 г соответствует двум исходным упаковкам по 200 г. Каталог не участвует в реальных продажах. [Своё Родное](https://svoe-rodnoe.ru/)
- Изображения находятся в `public/products/`. Формат WebP, 400×400, качество 80. Команда `yarn catalog:images` повторно подготавливает файлы из опубликованных источников.
- Настроить раздачу с префиксом `/static` через `@nestjs/serve-static`. Существующий файл возвращается с `200` и `Content-Type: image/webp`. Отсутствующий файл возвращает `404`.
- Nuxt использует путь `imageUrl` относительно origin API или проксирует `/static` на NestJS. При отсутствии картинки показывает заглушку.

## Доставка для демонстрационного сценария

Бесплатная доставка и утренний слот с 09:00 до 12:00. Адрес берётся из команды, а при его отсутствии используется демо-адрес. Сервер поддерживает ближайший доступный слот, «сегодня», «завтра» и ближайший запрошенный день недели. Слот текущего дня доступен до 09:00 по Москве. Для ближайшего дня недели выбирать первую дату с доступным слотом. Явно прошедшую дату или время вне поддерживаемого слота помечать как недоступные. Одна функция проверяет доступность для черновика и подтверждения. Дата в примерах API иллюстративна.

## Проверка стенда

`yarn demo:smoke` проверяет OpenAPI, CORS, фотографии, два текстовых сценария, повтор подтверждения и закрытие голосовой сессии без аудио. Запускайте на свежей выделенной демо-базе: проверка подтверждает заказ и вклад. Для другого адреса задайте `SMOKE_API_URL`, для CORS с другим origin — `SMOKE_FRONTEND_ORIGIN`. Если передать `SMOKE_AUDIO_PCM` с путём к сырой моно PCM-записи 16 кГц фразы заказа из ТЗ, проверка также проверит частичный и финальный ответ SpeechKit.


- Настроить CORS для адреса Nuxt. На стенде проверить HTTPS для микрофона, WSS и передачу WebSocket Upgrade через прокси. В Swagger описать HTTP-контракты. Голосовой протокол описан в [задаче WebSocket](./assistant-voice.md).
- На устройстве питча прогнать обе голосовые команды до успеха, затем повторить текстом. Проверить тишину, неподдерживаемую фразу, сбой облачного сервиса, недостаток средств и сетевой повтор подтверждения.
- Проверить выдачу картинок с устройства питча. Сбросить стенд и убедиться, что баланс снова 1 800 000 ₽, стартовая история на месте, траты относятся к текущему месяцу и каталог сохранён.
